# Практическая работа № 6. Подзапросы и логика предикатов

**Вариант 6.** Заказы, сумма платежей которых превышает сумму price+freight по позициям.

## 1. Основное решение (подзапросы)
Использован **скалярный подзапрос** для вычисления суммы платежей и суммы позиций, а также **коррелированный EXISTS** для проверки наличия платежей у заказа. 
Скалярный подзапрос возвращает одно значение (сумму) для каждого заказа, что позволяет сравнить их в `WHERE`.

## 2. Альтернатива через CTE
Предварительная агрегация `order_payments` и `order_items` до уровня заказа (`GROUP BY order_id`) позволяет соединить их с `orders` и сравнить суммы без повторных вычислений. 
Этот вариант обычно работает быстрее на больших данных, так как агрегация выполняется один раз, а не для каждой строки.

## 3. Проверка эквивалентности
Оператор `EXCEPT` в обе стороны вернул **0 строк** (diff_rows = 0). Это доказывает, что оба решения возвращают одно и то же множество заказов.

## 4. ANY и ALL
- **ANY**: заказы, в которых есть хотя бы одна позиция дороже 1000 (`price > 1000`). 
  `order_id = ANY (SELECT order_id FROM order_items WHERE price > 1000)`.
- **ALL**: заказы, в которых все позиции дороже 10 (`price > 10`). 
  `10 < ALL (SELECT price FROM order_items WHERE order_id = o.order_id)`.

## 5. Контрольные вопросы
1. **Чем коррелированный подзапрос отличается от независимого?**
   Коррелированный подзапрос ссылается на таблицу внешнего запроса и логически выполняется для каждой строки внешнего запроса. Независимый подзапрос выполняется один раз и не зависит от внешнего запроса.
2. **В каких случаях EXISTS логически удобнее IN?**
   `EXISTS` удобнее, когда нужно проверить **наличие** связанных строк (особенно при антисоединении через `NOT EXISTS`). `EXISTS` корректно работает с NULL в подзапросе, тогда как `NOT IN` с NULL может вернуть пустой результат. Кроме того, `EXISTS` может остановиться при первом совпадении, что быстрее.
3. **Почему скалярный подзапрос должен возвращать не более одной строки?**
   Потому что скалярный подзапрос используется в контексте, где ожидается **одно значение** (например, в сравнении `>`, `=`, или в `SELECT`). Если подзапрос вернет больше одной строки, СУБД выдаст ошибку `more than one row returned by a subquery used as an expression`.
