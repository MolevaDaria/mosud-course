# lab02 — Множества и мультимножества в SQL

Вариант 6: X = ES, Y = RJ. Учитываются только заказы со статусом `delivered`.

## Таблица мощностей

| Величина | Запрос | Значение |
|---|---|---|
| \|A\| (count(*)) | A | **2225** |
| \|A\| (count(DISTINCT)) | A | **1648** |
| \|B\| (count(*)) | B | **14143** |
| \|B\| (count(DISTINCT)) | B | **7672** |
| \|A ∪ B\| (UNION) | A UNION B | **8575** |
| \|A ∪ B\| (UNION ALL) | A UNION ALL B | **16368** |
| \|A ∩ B\| (INTERSECT) | A INTERSECT B | **745** |
| \|A − B\| (EXCEPT) | A EXCEPT B | **903** |
| \|B − A\| (EXCEPT) | B EXCEPT A | **6927** |

## Коммутативность и проверки

* **Коммутативность объединения:** `A ∪ B = B ∪ A` — обе мощности равны **8575**.
* **Коммутативность пересечения:** `A ∩ B = B ∩ A` — обе мощности равны **745**.
* **Некоммутативность разности:** `A − B` = **903**, `B − A` = **6927** (разность некоммутативна).
* **Пересечение через EXISTS:** результат совпадает с `INTERSECT` и равен **745**.

## Вывод о дубликатах

1. **Исходные запросы (A и B) возвращают мультимножества.** 
   В запросе A `count(*)` = 2225, а `count(DISTINCT product_id)` = 1648. Это значит, что один и тот же товар покупался в нескольких заказах, и в «сыром» результате строки повторяются. В SQL по умолчанию `SELECT` возвращает именно мультимножество (строки с дубликатами).

2. **`UNION` против `UNION ALL`.**
   `UNION` возвращает множество (удаляет дубликаты), поэтому мощность `A ∪ B` = 8575. 
   `UNION ALL` сохраняет дубликаты (возвращает мультимножество), поэтому мощность `A ∪ B` = 16368. 
   Разница (16368 − 8575 = 7793) — это количество повторяющихся строк, которые были отброшены оператором `UNION`.

3. **Другие операции.**
   * `INTERSECT` и `EXCEPT` (без ключевого слова `ALL`) по стандарту SQL также приводят результат к множеству (удаляют дубликаты).
   * Если бы мы использовали `INTERSECT ALL` или `EXCEPT ALL`, они бы сохраняли кратность элементов (возвращали мультимножество).
