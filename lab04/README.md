# Практическая работа № 4. Соединения отношений и сложные JOIN

**Вариант 6.** Сценарий: Повторные покупатели. 
Маршрут: `customers` по `customer_unique_id` → `orders`.

## 1. Кратность связей (Пункт 2)
* `customers` → `orders`: связь **1:N**. У одного реального человека (`customer_unique_id`) может быть несколько записей в таблице `customers` (разные `customer_id`), и каждая из них порождает заказ в `orders`.
* `orders` → `order_items`: связь **1:N** (в одном заказе много товаров).

## 2. Почему произошло размножение строк (Пункт 5)
В ошибочном запросе мы соединили `orders` и `order_items` напрямую. Если в заказе было 6 товаров, строка заказа дублировалась 6 раз. В результате `count()` считал не количество заказов, а количество позиций. Исправление через CTE (`WITH order_sums`) сначала агрегирует позиции до уровня заказа, а затем соединяет с клиентами, сохраняя правильную кратность 1:1.

## 3. Реляционная алгебра для основного запроса (Пункт 7)
1. **Соединение (⋈)**: `customers ⋈_{customer_id} orders`.
2. **Проекция (π)**: выборка `customer_unique_id`, `order_id`, `order_purchase_timestamp`.
3. **Агрегация (γ)**: группировка по `customer_unique_id`, вычисление `count(order_id)`, `min(timestamp)`, `max(timestamp)`.
4. **Выборка (σ)**: фильтрация `σ_{total_orders > 1}`.

## 4. Контрольные вопросы
1. **Почему соединение order_items и order_payments по одному order_id может завысить SUM?**
   Если в заказе 3 товара и 2 платежа, прямое соединение даст 3 × 2 = 6 строк. Сумма будет посчитана 6 раз (каждый товар умножится на каждый платеж), что завысит итоговую сумму.
2. **В чём отличие LEFT JOIN ... WHERE right.id IS NULL от NOT EXISTS?**
   `LEFT JOIN ... IS NULL` сначала выполняет соединение (что может быть ресурсоемко при больших таблицах), а потом фильтрует. `NOT EXISTS` использует полу-соединение и останавливается, как только находит первое совпадение, что часто работает быстрее и лучше оптимизируется планировщиком.
3. **Как представить эквисоединение через декартово произведение и выборку?**
   Эквисоединение `R ⋈_{R.a = S.b} S` математически эквивалентно `σ_{R.a = S.b}(R × S)`. Сначала берется декартово произведение (все пары строк), а затем выборка (WHERE) оставляет только те пары, где условие равенства выполняется.
